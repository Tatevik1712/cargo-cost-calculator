## Обзор

Cargo Cost Calculator — веб-приложение для сравнения стоимости грузоперевозки
у трёх транспортных компаний: «Деловые линии» (через внешний API),
РТТК и БРЛ (расчёт по локальным прайс-файлам). Пользователь вводит параметры
груза и маршрут, получает три предложения и рекомендацию по выбору.

```
┌─────────────────┐        HTTP/JSON        ┌──────────────────────┐
│   Frontend       │ ───────────────────────▶│   Backend (FastAPI)  │
│  React + Vite    │◀─────────────────────── │                      │
│  TanStack Router │                          │  main.py             │
└─────────────────┘                          │  ├─ auth.py          │
                                              │  ├─ local_calculator │
                                              │  └─ dellin_client    │
                                              └──────┬───────┬───────┘
                                                     │       │
                                          читает     │       │  HTTP
                                       xlsx/csv       │       ▼
                                                     ▼   ┌─────────────┐
                                          ┌──────────────┐│ API «Дело-  │
                                          │ backend/data/ ││ вые линии»  │
                                          │ RTTK.xlsx     │└─────────────┘
                                          │ BRL.xlsx      │
                                          └──────────────┘
```

## Backend

Стек: **Python, FastAPI, Pandas, Pydantic, JWT (python-jose/pyjwt), Uvicorn**.

### Структура

```
backend/
├── app/
│   ├── models/
│   │   └── schemas.py          # Pydantic-модели запроса/ответа
│   └── services/
│       ├── auth.py             # JWT-аутентификация, роли
│       ├── dellin_client.py    # Клиент API "Деловые линии"
│       └── local_calculator.py # Парсинг прайсов РТТК/БРЛ, расчёты
├── config/
│   └── settings.py             # HOST, PORT и прочие настройки
├── data/
│   ├── RTTK.xlsx                # Прайс РТТК (загружается через /admin/upload)
│   └── BRL.xlsx                 # Прайс БРЛ
└── main.py                      # FastAPI-приложение, роуты
```

### Ключевые компоненты

**`main.py`** — единственная точка входа. Регистрирует роуты:

| Метод | Путь | Доступ | Назначение |
|---|---|---|---|
| POST | `/api/auth/login` | публичный | Аутентификация, выдача JWT |
| GET | `/api/auth/me` | авторизован | Информация о текущем пользователе |
| GET | `/api/admin/files` | admin | Список текущих прайс-файлов |
| POST | `/api/admin/upload` | admin | Загрузка нового прайс-файла (rttk/brl) |
| POST | `/api/v1/calculate` | публичный | Расчёт стоимости у трёх перевозчиков |
| GET | `/api/v1/cities` | публичный | Динамический список городов |

**`local_calculator.py` (`LocalCalculatorService`)** — сердце бизнес-логики:
- при инициализации ищет файлы РТТК/БРЛ в `backend/data/` по ключевым словам
  в имени файла;
- `_load_dataframe()` — универсальная загрузка xlsx/xls/csv с автоопределением
  кодировки и разделителя для CSV;
- `_find_price_in_data()` — построчный разбор прайса: ищет строку-заголовок
  маршрута (по совпадению названий городов "туда" и "обратно"), затем строку
  с нужным тоннажом машины, возвращает цену из нужной колонки (прямое или
  обратное направление);
- `calculate_totals()` — расчёт суммарного объёма (м³) и веса (кг) партии;
- `_determine_required_capacity()` — подбор тоннажа машины по весу (1.5 / 3 /
  5 / 10 / 15 / 20 тонн);
- `get_available_cities()` — сканирует оба прайса, извлекает названия городов
  из заголовков маршрутов (`_split_route`, `_extract_city_candidates`),
  нормализует написание (`_normalize_city_name`) и возвращает **уникальный**
  отсортированный список — именно он отдаётся через `GET /api/v1/cities`.

**`dellin_client.py`** — асинхронный HTTP-клиент к API «Деловых линий»;
результат приводится к общему формату `OfferResponse` наравне с РТТК/БРЛ.

**`auth.py`** — простая JWT-аутентификация поверх словаря `USERS` (роли
`admin`/`user`), функции `authenticate`, `create_access_token`,
`get_current_user`, `require_admin` как FastAPI-зависимости.

**`schemas.py`** — Pydantic-модели: `CargoRequest` (входные параметры груза
и маршрута), `OfferResponse` (единичное предложение перевозчика),
`CalculationResponse` (агрегированный ответ по всем трём компаниям).

### Поток расчёта (`POST /api/v1/calculate`)

1. Считаются `total_volume`/`total_weight` по формулам объёма/веса.
2. Параллельно запускаются: асинхронный запрос к API «Деловых линий»
   (`asyncio.create_task`) и синхронные расчёты РТТК/БРЛ по локальным файлам.
3. Результаты собираются в список `offers`, сортируются по цене.
4. Формируется текстовая рекомендация (самый дешёвый + альтернатива).
5. Ответ возвращается фронту в формате `CalculationResponse`.

## Frontend

Стек: **React, Vite, TypeScript, TanStack Router, Tailwind (shadcn/ui), lucide-react**.

### Структура (значимые файлы)

```
frontend/
├── src/
│   ├── config.ts                    # API_BASE_URL
│   ├── lib/
│   │   ├── calc.ts                  # fetch-обёртки к backend API
│   │   ├── auth.ts                  # logout и пр.
│   │   └── pdf.ts                   # генерация PDF-отчёта
│   ├── hooks/
│   │   └── useAuth.ts               # текущий пользователь
│   └── pages/
│       └── CargoCalculator.tsx      # главный экран калькулятора
```

### Поток данных на фронте

1. При монтировании `CargoCalculator` вызывает `getCitiesFromBackend()` —
   единственный источник списка городов (без статического fallback).
   Состояния `citiesLoading` / `citiesError` явно отражаются в UI.
2. Пользователь заполняет форму (города, вес, габариты, количество мест).
3. Валидация — на клиенте, по лимитам `LIMITS` (вес, габариты, количество).
4. По нажатию «Рассчитать» — `POST /api/v1/calculate` через `fetch` с
   заголовком `ngrok-skip-browser-warning` (нужен только при тестировании
   через бесплатный ngrok, безвреден на localhost/проде).
5. Результат сортируется (доступные — по возрастанию цены, недоступные — в
   конец), выводятся карточки трёх перевозчиков + сводная рекомендация.
6. Доступна генерация PDF-отчёта (`generateReport()`) по текущему расчёту.

## Тестовое окружение (ngrok)

Для предоставления доступа тестировщикам без деплоя используется связка из
трёх терминалов:

```
Терминал 1: frontend % npm run dev            # Vite dev-server (обычно :8080)
Терминал 2: cargo-cost-calculator % ngrok http 8000   # туннель к backend
Терминал 3: cargo-cost-calculator % ngrok http 8080   # туннель к frontend
```

Особенность бесплатного ngrok: первый запрос с нового браузера получает
HTML-страницу-предупреждение вместо ответа API — что выглядит как ошибка
CORS. Решение — заголовок `ngrok-skip-browser-warning: true` во всех
fetch-запросах (уже реализовано в `calc.ts`).

## Модель данных прайсов (важно для доработки парсера)

Прайс-файлы РТТК/БРЛ — это Excel-таблицы без заголовков колонок, где:
- строка-разделитель маршрута выглядит как `"Город А – Город Б/ Город Б - Город А"`
  (главный и обратный маршрут через `/`, разделитель городов — `–`, `—` или ` - `);
- следующие 6 строк — тарифы по тоннажу вида
  `"Автомобиль Грузоподъемностью 1,5 тонн"` с ценой в 1-й колонке (прямое
  направление) и, если есть, во 2-й колонке (обратное направление).

Если формат прайсов изменится (например, появится третья колонка или другой
разделитель маршрутов) — правки нужны в `_split_route`,
`_extract_city_candidates` и `_find_price_in_data` (`local_calculator.py`).
