## Что уже реализовано

### Backend (FastAPI, `backend/`)
- `main.py` — точка входа, роуты:
  - `POST /api/auth/login` — вход, выдача JWT
  - `GET /api/auth/me` — данные текущего пользователя
  - `GET /api/admin/files` — список загруженных прайс-файлов (только admin)
  - `POST /api/admin/upload` — загрузка нового прайс-файла РТТК/БРЛ (только admin)
  - `POST /api/v1/calculate` — основной расчёт стоимости по трём перевозчикам
  - `GET /api/v1/cities` — динамический список городов, собранный из прайс-файлов
- `app/services/local_calculator.py` — парсинг прайсов РТТК и БРЛ (xlsx/xls/csv),
  расчёт объёма/веса партии, подбор тоннажа машины, поиск цены по маршруту,
  сбор уникального списка городов из заголовков маршрутов в прайсах.
- `app/services/dellin_client.py` — асинхронный клиент к API «Деловых линий».
- `app/services/auth.py` — JWT-аутентификация, роли `admin`/`user`.
- `app/models/schemas.py` — Pydantic-схемы запроса/ответа (`CargoRequest`,
  `CalculationResponse`, `OfferResponse`).
- CORS открыт (`allow_origins=["*"]`) — для тестового режима через ngrok.

### Frontend (React + Vite + TanStack Router, `frontend/`)
- `src/pages/CargoCalculator.tsx` — главный экран калькулятора: форма
  (города, вес, габариты, количество мест), вызов `/api/v1/calculate`,
  отображение результатов трёх перевозчиков, генерация PDF-отчёта.
- `src/lib/calc.ts` — обёртки над `fetch` для `/api/v1/cities` и
  `/api/v1/calculate`.
- `src/config.ts` — `API_BASE_URL`, читается из переменной окружения Vite.
- Список городов теперь **полностью динамический**, тянется с бэкенда
  (см. ADR-004 в `DECISIONS.md`), статический fallback-список удалён.
- Тип доставки «Экспресс» удалён — доступна только «Авто».

## В разработке / известные незакрытые вопросы

- Нет автоматических тестов (backend и frontend).
- Нет обработки конкурентной загрузки прайс-файлов через `/api/admin/upload`
  (гонка при одновременной загрузке двух файлов одного перевозчика).
- `main.py` ранее содержал задублированные объявления роутов
  (`/api/auth/login`, `/api/auth/me`, `/api/admin/files`, `/api/admin/upload`) —
  требуется финальная чистка (см. `TASKS.md`).
- Нормализация названий городов (`_normalize_city_name`) покрывает только
  известные варианты написания Санкт-Петербурга и Ростова-на-Дону — при
  добавлении новых перевозчиков список нужно будет расширять.
- Тестирование ведётся через ngrok (см. блок «Запуск» ниже) — для продакшена
  нужен постоянный домен/деплой.

## Какие решения были приняты

Полный лог решений — в `DECISIONS.md`. Кратко:
- Цены хранятся в Excel/CSV-файлах, а не в БД (ADR-001).
- Список городов вычисляется динамически из прайсов, а не задаётся статично
  во фронтенде (ADR-002).
- Для локальной разработки с доступом извне используется двойной ngrok-туннель
  (порт 8000 — backend, порт 8080 — frontend) (ADR-003).
- Все fetch-запросы к бэкенду с фронта должны явно обрабатывать ошибку и
  показывать её пользователю, без тихих fallback-ов на статичные данные (ADR-004).
- Тип доставки «Экспресс» убран из UI и запроса — поддерживается только «Авто» (ADR-005).

## Какие есть ограничения

- Интеграция с «Деловыми линиями» — единственный внешний API, зависит от
  доступности стороннего сервиса.
- Прайсы РТТК/БРЛ — неструктурированные Excel-таблицы с шапками маршрутов в
  свободном тексте; парсинг основан на эвристиках (регулярные выражения,
  поиск разделителей «–», «—», «-», «/»). Любое изменение формата исходных
  файлов может сломать парсинг.
- Бесплатный ngrok показывает интерстициальную страницу-предупреждение при
  первом обращении — все fetch-запросы с фронта обязаны слать заголовок
  `ngrok-skip-browser-warning: true`, иначе браузер получает CORS-ошибку.

## Что делать следующим шагом

1. Убрать задублированные роуты в `main.py` (см. `TASKS.md`, задача #1).
2. Покрыть `local_calculator.py` unit-тестами (парсинг цен, сбор городов,
   определение тоннажа).
3. Добавить структурированное логирование вместо `print()`.
4. Продумать хранение прайсов не в файловой системе контейнера, а во
   внешнем сторадже (или БД) — на случай передеплоя.

## Возможные риски

- Изменение структуры прайс-файлов перевозчиками (новые колонки, другой
  формат заголовков) без синхронной правки парсера в `local_calculator.py`.
- Истечение бесплатных ngrok-сессий во время демонстрации — URL меняется
  при каждом перезапуске, нужно каждый раз обновлять `VITE_API_BASE_URL`.
- Хранение прайс-файлов и JWT-логики без внешнего секрет-менеджера —
  не готово к реальному продакшену без доработки безопасности.
